# Отчёт по уроку 6

## Тестовый C++ проект

В исходном `demo/main.cpp` не было точки с запятой:

```cpp
std::cout << 42 << std::endl
```

Агент выполнил такие tool calls:

1. `list_files` — увидел `CMakeLists.txt` и `main.cpp`.
2. `read_file` — прочитал оба файла.
3. `run_command` — выполнил `cmake -S . -B build`.
4. `run_command` — выполнил `cmake --build build --config Debug`.
5. Получил ошибку компилятора `C2143`: перед `return` не хватает `;`.
6. `write_file` — записал исправленный `main.cpp`.
7. `run_command` — повторно собрал проект без ошибок.
8. `run_command` — запустил `build/Debug/demo_app.exe`.

Изменение кода:

```diff
-    std::cout << 42 << std::endl
+    std::cout << 42 << std::endl;
```

Программа завершилась с кодом 0 и напечатала `42`.

Во время первых опытов маленькая модель предлагала настроить CMake прямо в
каталоге исходников и пыталась закончить работу после одной настройки. Эти
действия были отклонены. В агент добавлены отдельный каталог `build`, проверка
успешной сборки и запрет завершения до выполнения всей задачи.

## Ответы на вопросы

1. До первой сборки агент получил список файлов, прочитал `CMakeLists.txt` и
   `main.cpp`, затем настроил проект командой `cmake -S . -B build`.
2. Инструмент `run_command` вернул модели код завершения, stdout и stderr
   компилятора. В stderr была указана пропущенная точка с запятой.
3. Модель вызвала `list_files`, а затем `read_file`. Сама модель не имеет
   прямого доступа к диску.
4. Обычный ответ — это только текст. Tool call содержит имя инструмента и
   аргументы в JSON. Код агента решает, разрешено ли выполнить это действие.
5. Команду запускает Python, а не LLM. Без возвращённого результата модель не
   узнает, успешно ли завершилась команда и что написал компилятор.
6. Одного действия недостаточно. Цикл позволяет прочитать файл, собрать
   проект, увидеть ошибку, исправить её и снова проверить результат.
7. Неограниченный shell позволяет удалить или испортить файлы, прочитать
   секреты, выполнить сетевые команды и запустить вредную программу. Поэтому
   здесь используются белый список команд, проверка путей и тайм-аут.

## Практическая работа с lesson 5

Для проверки использован проект `assignments/lesson05/pirogov` из отдельной
ветки lesson 5. Он был открыт во временном Git worktree, поэтому файлы lesson 5
не попадают в ветку lesson 6.

### Анализ

Агент вызвал `list_files` и прочитал:

- `CMakeLists.txt`;
- `README.md`;
- `include/chat.hpp`;
- `src/chat.cpp`;
- `src/config.cpp`;
- `src/http_client.cpp`;
- `src/main.cpp`;
- `tests/chat_test.cpp`.

Проект состоит из C++17-клиента локального `llama-server`, библиотеки
`chat_core`, консольной программы `local_chat` и теста `chat_test`.

### Сборка и тесты

Агент выполнил:

```text
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Все команды завершились с кодом 0. Результат тестов:

```text
1/1 Test #1: chat_test ... Passed
100% tests passed, 0 tests failed out of 1
```

Ошибок сборки не было, поэтому агент не изменил файлы lesson 5. Его `git diff`
для этого проекта пустой.

### README

Существующий README lesson 5 уже содержит описание, структуру, зависимости,
команды сборки и запуска, пример использования, тесты и ограничения модели.
Изменять его не потребовалось. Это решение принято, потому что все пункты
задания уже выполнены и новые выдуманные возможности добавлять нельзя.

### Code review

Вывод локальной модели был слабым: она сообщила, что проблем и пропущенных
тестов нет, а также вывела неточный и повторяющийся список файлов. Этот вывод
отклонён. Факт успешной сборки не доказывает отсутствие проблем.

При ручной проверке найдены разумные направления для улучшения:

- добавить тесты неправильных значений конфигурации;
- добавить тесты повреждённых ответов сервера;
- отдельно проверить сетевые ошибки и HTTP-коды.

В рамках lesson 6 эти изменения не вносились: задача была изучить работу
агента, а ветка должна содержать только решение lesson 6. Было принято только
предложение не менять рабочий код lesson 5 после успешной сборки и тестов.
